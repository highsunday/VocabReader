# Bug Fix: 修正官網與 GitHub README 的 GIF 色彩轉換

## 1. Bug Overview

GitHub README 與 VocabReader 官網使用的操作 GIF 出現偏灰、暖米色與灰綠色階不自然，
且大面積淺色背景可見規律點陣。現有公開資產混用不同產生方式：七個舊 GIF 的
首幀只使用 47–63 色且為 800×500，兩個後期 GIF 使用 254–255 色且為
1100×660。舊產生管線又使用 Bayer 抖色，因此將調色盤誤差呈現為視覺網點。

官網 `website/public/assets/` 又獨立複製 README 的三個 GIF，目前兩個公開表面
容易漂移，無單一可重現的媒體建置與驗證入口。

## 2. Fix Objective

- 由保留的真實產品錄影或 RGB 影格重新產生公開 GIF，不從已低色化的 GIF 反向轉檔。
- 在單一 FFmpeg 轉換中依 BT.709 錄影資訊解碼並縮放，不再產生無色彩標記的
  `yuv420p` 中間 MP4。
- GIF 使用完整 256 色調色盤，並使用不會產生規律網點的誤差擴散抖色。
- GitHub README 與官網參照相同產生結果；官網三個 GIF 必須與 repository
  對應檔案位元級一致。
- 保留官網現有版型、雙語文案、學習路徑順序與真實產品證據定位。

## 3. Acceptance Criteria

- **Scenario 1：公開 GIF 不再使用低色數 Bayer 管線**
  - **Given** repository 保留的原始錄影與 RGB 影格
  - **When** 執行公開 GIF 產生器
  - **Then** 產生器使用 256 色調色盤與非 Bayer 抖色，不寫出 `yuv420p` 中間檔

- **Scenario 2：GitHub README GIF 色彩一致**
  - **Given** README 參照的九個操作 GIF
  - **When** 以共用產生器重建
  - **Then** 每個檔案都是可解碼的動畫 GIF，並使用 256-entry 調色盤建置
  - **And** 暖米色、深綠、灰綠與書封顏色不出現規律點陣或明顯整體色偏

- **Scenario 3：官網使用相同資產**
  - **Given** 官網展示 AI Tutor、間隔複習與多語言切換 GIF
  - **When** 產生器同步官網資產
  - **Then** 官網的三個 GIF 與 `docs/readme-assets/` 同名檔案位元級一致

- **Scenario 4：官網與 README 不回歸**
  - **Given** 更新後的媒體資產
  - **When** 執行媒體合約測試、官網測試與 production build
  - **Then** README 所有 GIF 路徑存在，官網結構與雙語合約通過，且建置成功

- **Scenario 5：實際呈現可用**
  - **Given** desktop 與 mobile 官網 viewport
  - **When** 瀏覽包含新 GIF 的首頁
  - **Then** GIF 正確縮放、無水平 overflow、無明顯色偏或網點，且不造成布局移位

## 5. Implementation Notes

- 產生器納入 repository 的 `scripts/`，而不繼續依賴不可追蹤的一次性命令。
- 原始畫面為 BT.709 limited-range 錄影時，依該標記解碼成 RGB 後直接進入
  `palettegen` / `paletteuse`；不再先編碼第二份 H.264 MP4。
- 使用 `sierra2_4a` 誤差擴散取代 Bayer，降低平坦 UI 表面的規律紋理。
- 以穩定幀率、尺寸與必要的時間壓縮控制檔案大小，不犧牲介面文字可讀性。

### Hypotheses and Decisions

- Red phase 首先確認現有資產的真實回歸：產生器不存在，且 `ask-ai-context.gif`
  首幀只有 63 色。
- 前一輪 `diagnose` 控制實驗顯示，直接由 RGB 畫面產生 256 色 GIF 的像素誤差約
  `0.0064`，而先經無色彩標記 `yuv420p` 中間檔約為 `0.074`；因此修正點放在
  中間編碼邊界，不只是把最後調色盤調大。
- Bayer 會把平坦 UI 表面的調色盤誤差排成規律網點；改用 `sierra2_4a`
  保留視覺細節且不產生固定點陣。
- 產品網站來源被 Git 忽略，但在當前 workspace 中由同一產生器更新；使用者後續
  明確要求上傳後，已將 README 資產推送至 `main`，並以非 force-push 方式將
  已驗證的 `website/dist` 發布至 `gh-pages`。
